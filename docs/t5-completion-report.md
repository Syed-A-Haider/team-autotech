- **Why Choose Us (T5.6):** the hover-expanding strip (a CSS Module animating flex, padding, font size and max-height, with descriptions hidden on phones and until hover on desktop, and four tab stops that did nothing) is now four always-visible cards. No new block: the `ul` is `reveal-stagger`, each card has a `stripe-draw` top stripe, a static wedge and `lift`. The `@motion` guards now also run at desktop. The CSS Module is gone. - **Reviews carousel (T5.7):** the transform slider is now a native scroll-snap track, so swipe, momentum and no-JS scrolling are the browser's. The centre card is 896px from `lg` (a fixed 56rem, and the track bleeds into the section padding), the next card peeks in on phones, one set of 44px arrows sits under the track on phones and on its edges from `lg`, dots have a real tap target, and Left, Right, Home, End and clicking a neighbour work. Every route wraps, swipe included, through a window of slides that turns around the current one (CSS `order`, no clones), and the neighbouring cards tint on hover. `currentIndex` is still state, derived from the scroll, with a target lock so a long button scroll does not flick through every card. It also moves on by itself every 3s while on screen, with a pause button, and stops once the visitor uses it. No new block, no mouse drag. JS +0.81 KB and CSS +0.87 KB gzipped
- **Proven so far:** the production CSS keeps the new syntax, reduced motion starts no animation, the guards fail when a reveal is captured or missing, and the reveals behave the same in both engines
- **Next:** T5.8, Carousel depth and polish

## Gotchas found

- Playwright's `test.use({ reducedMotion: 'reduce' })` is silently ignored. Use `test.use({ contextOptions: { reducedMotion: 'reduce' } })` (T5.1)
- `overflow-hidden` makes a scroll container that captures `view()` timelines, so a reveal inside it never runs. Use `overflow-clip` (T5.3)
- A click test on a full-width `summary` passes on the old FAQ, because the old summary was already full width. The bug was the padding on `details`, so the test clicks the row 8px in. A page-wide "an animation is running" check can be satisfied by an unrelated transition: read `el.getAnimations()` on the element under test (T5.2)
- `overflow: clip` on `::details-content` clips default focus outlines on links inside it, so they need an inset ring. Tailwind `group-open:` only matches descendants, so a `before:` bar on the `details` itself needs `open:before:` and `pointer-events-none` (T5.2)
- Tailwind scans the whole project, `docs/*.md` included, so naming a utility in prose or a brief emits it (`reveal-left`, the 110% scale utilities). A real first use is what guarantees it (T5.3, T5.4)
- A guard that only checks "nothing is faded" cannot tell a working reveal from no reveal. T5.3 added guards that need reveals to exist, have a live timeline and hold no fill. They caught a wrong slug (`scorpion-x-series`, really `scorpion-x-series-immobiliser`) that had been testing a 404
- A reveal below the fold is hidden at load, JavaScript on or off, so the JS-off guard scrolls first. `requestAnimationFrame` never fires in `page.evaluate` with JavaScript off, so `scrollThrough` scrolls one `evaluate` per step (T5.3)
- WebKit has no `layout-shift` entries, so the CLS guard is skipped there. It updates scroll-driven values one frame after `scrollTo`, so poll. A cold dev server can time out one test on a first run (T5.3)
- Side slides need an `overflow-clip` ancestor: a full-width card sliding in pushes the page 8px wider at 375, and the end-of-scroll guards cannot see it. `animation-delay` does nothing on a scroll timeline, so stagger shifts `animation-range`. Individual `translate` and `scale` skip inline boxes, so reveal `block` elements (T5.3)
- The sticky Navbar is 65px tall (`h-16` plus a 1px border), so `scroll-padding-top` is `calc(4rem + 1px)` (T5.3)
- A `:active` rule in a custom block ties a Tailwind hover scale utility on specificity and loses on a mouse click, so `press` is written `:active:not(:disabled)` (T5.4). A custom `@utility` hover rule gets no hover media query for free (T5.4)
- A guard that reads elements cannot see `::before` or `::after`, and a missing pseudo-element reads `scale: none` (meaning 1). `InteractionAudit.scaleX` returns `NaN` for one that does not exist (T5.4)
- Checking that something did NOT happen passes at once if you only poll. Wait a few frames first (`settleFrames`). Playwright has no `expect.soft.poll`: poll first, then check softly (T5.4)
- `--ease-settle` suits things that arrive and stay. It is wrong for an effect that must stay visible while it moves. Judge a timed effect from stepped frames: pause `getAnimations()` at a set `currentTime` and screenshot (T5.4)
- `addInitScript` runs before `document.documentElement` exists, so appending a style there throws and stops a layout-shift observer after it from registering (CLS reads a false 0). Register the observer first (T5.5)
- The reduced-motion guard polls `runningAnimationCount` to 0, so a timed effect that lost its guard just finishes and passes. The first-frame check samples `main.getAnimations()` on every frame from first paint (T5.5)
- Chrome counts a font-swap text shift only when the text was visible at first paint. A page fade from 0 hid it. The 404 numeral is 228.8px wide in the fallback font and 247.5px in Inter Black, so its start edge moves 9.4px (CLS 0.002) when Inter arrives. A fade from 0 on the numeral removes it. On a very slow connection the 0.002 can return (T5.5)
- Elements inside `PageTransition` carry its opacity, so a computed opacity on the h1 alone misses it (the load-in guard multiplies up the ancestors). `sheen`'s resting spot is the only value a touch test can compare to, so wait for the load sweep first (T5.5)
- A script that imports `@playwright/test` resolves it from the script's own folder, so a throwaway script must be copied into the repo root to run and deleted after (T5.5)
- A decoration faded with `opacity-*` reads as faded for ever and fails `fadedElementCount`. Use a colour tint (`bg-accent/10`). Tailwind v4 `divide-y` draws `border-bottom`, not `border-top` (T5.6)
- `offsetWidth` and `offsetHeight` ignore transforms, so with the left edge from `getBoundingClientRect` they prove "no layout change" while a lift or reveal moves things vertically. Do not use `offsetLeft` or `offsetTop`: WebKit measures them from an animated, unpositioned ancestor while it reveals, so they read 0 and then a real value with no layout change (T5.6)
- A right-aligned element whose width depends on text moves its left edge when the web font replaces the fallback. Phone size never showed it, because the header call button is hidden below `lg`. Only the desktop run of the layout-shift guard found it (T5.6)
- `overflow-x: auto` makes a `visible` `overflow-y` compute to `auto`, so a scroller that holds scaled or tilted children would also scroll vertically. Use `overflow-y-hidden` and pad the track (T5.7)
- A focused scroll-snap track moves one snap per arrow key by itself, so a key handler that also calls `scrollTo` can move twice. `preventDefault` fixes it, but the double move only appears with reduced motion (an instant `scrollTo` finishes before the native step). A smooth `scrollTo` overrides the native step, so the normal-motion run of the same test cannot catch a missing `preventDefault` (T5.7)
- A `view()` timeline on an element inside a scroll container binds to that container, so per-slide effects in the reviews track need `view(inline)`, and `revealAudit` (which only counts timelines on the page scroller as live) will flag them until it is taught about the track (T5.8)
- A slide's `offsetLeft` needs the track to be `relative` (it is the slide's `offsetParent`). It also ignores transforms, so the nearest-slide maths survives T5.8's scale and tilt (T5.7)
- Tailwind 4.3.3 ships `scrollbar-none`, and `[--gap:--spacing(3)]` and `before:w-[calc((100%_-_var(--slide))_/_2_-_var(--gap))]` (underscores for spaces) generate the right CSS. `eslint-config-next` enables only six jsx-a11y rules and none about clicks, so an `onClick` on a slide `div` passes lint (T5.7)
- In jsdom, `requestAnimationFrame` is real and `scrollTo` and `matchMedia` are missing. A spy on `requestAnimationFrame` also counts the test's own frame request. Some new tests passed before the code existed (they test a guard that nothing triggers yet), so they were proven by removing the guard (T5.7)
- A synthetic touch fling in headless Chromium (CDP `Input.dispatchTouchEvent`) leaves a scroll-snap track between cards, and so does a bare snap row with no app code. Hold the finger still for a moment before lifting if a test needs the snap (T5.7)
- Reordering slides under a snapped scroller: Chromium and WebKit re-snap to the slide they were snapped to after the layout changes, so `scrollLeft` read afterwards already includes the move. Capture `scrollLeft` before the change and set the new value outright, never `+=`. The jsdom test fakes the re-snap on any layout-forcing read, and it only fails on `+=` once the fake follows the slide the view was snapped to, not the current one (T5.7)
- Chromium fires `scrollend` before the animation frame that releases a button scroll's target lock. A handler that clears its debounce timer and then bails on the lock loses the settle for good (T5.7)
- React replays a click made while the page hydrates ahead of the render that applies a `useSyncExternalStore` client value, so a press can run in the server-shaped render and then be clobbered by the layout effect. Park it and carry it out in that effect. jsdom's React does not interleave them, so a Vitest hydration test passed with the fix removed (deleted as false assurance); the proof is `A press made as the page loads still lands` in Playwright, which reloads and clicks four times (about half of early clicks failed before the fix) (T5.7)
- Swapping the icon under a mouse pointer (the pause and play button) makes the browser send the leave event to the removed node, so React's `onPointerLeave` never fires and the carousel stays "hovered". Give the icons `pointer-events-none` so the button is the target (T5.7)
- Playwright's mouse is a mouse: a click leaves the carousel hovered, so a test that wants autoplay running moves it away. `page.clock.install()` after the page has loaded keeps time flowing, and `fastForward` fires the due timer once. A fixed number of frames after a hover was flaky in WebKit (6 of 8 runs): the root's `data-autoplay` (`running` or `held`) is what a test waits for (T5.7)
- WebKit can read two sideways wheel swipes in quick succession as one gesture, and a wheel swipe sent before the page hydrates scrolls a plain track with hard ends. `HomePage.swipeReviews` waits for the window first and takes `'scroll'` for tests that chain swipes (T5.7)
