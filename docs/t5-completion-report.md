# T5 Completion Report

Phase T5: motion and wow factor, a CSS-first motion system in 12 small tickets (T5.1 to T5.12). A running document. At the end of each ticket, rewrite it as one short summary: fold the new ticket into the Summary, Decisions and Gotchas, keep one line per ticket in the Timeline, and drop detail that no longer helps. Do not just append. Facts come from git history, PR bodies, the docs and measured runs. Anything unverified goes under Not verified.

## Summary

Done so far: T5.1 to T5.4 (4 of 12).

- **Foundation (T5.1):** motion tokens, a `motion.css` block scaffold with the rules every block follows, a `@motion` guard suite that reads computed style, and a measured mobile baseline. No visible effect by design
- **First block (T5.2):** `details-expand`. The FAQ now toggles from the whole padded row (a functional bug fix: only the text and chevron worked before) and opens with a fade-up, a rotating chip and an accent edge bar. Chromium also animates the height, in and out. Safari and Firefox get the fade and an instant close. The mobile menu categories share the same block
- **Scroll reveals (T5.3):** `reveal`, `reveal-left`, `reveal-right`, `reveal-stagger` and `stripe-draw`, all on `view()` timelines with no JavaScript. Applied to `SectionHeading` only: the faded number and the h2 fade up and the racing stripe draws out, on every numbered service section, closing band, Related Services and the About headings. `overflow-clip` replaced `overflow-hidden` on `SectionShell`, `EnquiryBand` and the About panel, so the timelines bind to the page. `scroll-padding-top` clears the sticky Navbar on anchor jumps
- **WebKit (T5.3):** Playwright now runs Chromium and WebKit (Safari 26.5 engine), because no iPhone is available. The whole suite passed on WebKit unedited before T5.3 started. This pulls part of T6.1 forward (Firefox is left)
- **Press and hover polish (T5.4):** `press`, `lift`, `sheen`, `underline-draw` and `pulse-ring`, all CSS. A tap shrinks a button, card, menu toggle, social icon or the WhatsApp widget instantly and eases back. Primary buttons get one sheen sweep, cards rise and tilt their icon, the Navbar links and dropdown titles draw an underline, and the widget pulses twice 2s after a full page load. `press` owns each element's transition and other blocks add a duration slot, so two effects on one element cannot override each other. Every hover rule sits in its own hover media query, so nothing sticks on touch. `ServiceCard` also gained a keyboard focus ring. 26 `@interaction` tests per browser, and the reduced-motion guard now reads pseudo-elements
- **Proven so far:** the production CSS keeps the new syntax, reduced motion starts no animation, the guards fail when a reveal is captured or missing, and the reveals behave the same in both engines (spike table below)
- **Next:** T5.5, homepage hero load-in, services grid reveal and the `PageTransition` decision

## Gotchas found

- Playwright's `test.use({ reducedMotion: 'reduce' })` is silently ignored. Use `test.use({ contextOptions: { reducedMotion: 'reduce' } })` (T5.1)
- `overflow-hidden` makes a scroll container that captures `view()` timelines, so a reveal inside it never runs. Proven in T5.3 (3 to 17 captured reveals per page). Use `overflow-clip`
- A click test on a full-width `summary` passes on the old FAQ, because the old summary was already full width and its corner is its text. The bug was the padding on `details`. The test clicks the `details` row 8px in, which is padding on old code and summary on new (T5.2)
- A page-wide "an animation is running" check can be satisfied by an unrelated transition (the old chevron rotation made a motion test pass on old code). Read `el.getAnimations()` on the element under test (T5.2)
- `overflow: clip` on `::details-content` clips default focus outlines on links inside it, so those links need an inset ring (T5.2)
- Tailwind `group-open:` only matches descendants, so a `before:` bar on the `details` itself needs `open:before:`. The bar also needs `pointer-events-none`, or its 4px strip would swallow taps meant for the summary (T5.2)
- Tailwind 4.3.3 inlines `@import`ed files before the `@utility` pass, so `@utility` works in `motion.css`, and `@keyframes` belong at its top level. Lightning CSS keeps `@supports selector(...)` and `transition-behavior` in the production build (T5.2)
- A guard that only checks "nothing is faded" cannot tell a working reveal from no reveal. T5.3 added guards that need reveals to exist, have a live timeline on the page scroller and hold no fill. They caught a wrong test slug (`scorpion-x-series`, really `scorpion-x-series-immobiliser`) that had been quietly testing a 404
- A reveal below the fold is hidden at load with `backwards` fill, JavaScript on or off. The JS-off guard has to scroll first (T5.3)
- `requestAnimationFrame` inside `page.evaluate` never fires with JavaScript off, so `scrollThrough` hung. It now scrolls one `evaluate` call per step (T5.3)
- WebKit has no `layout-shift` entries, so the CLS guard would always pass there. It is skipped on WebKit (T5.3). WebKit also updates scroll-driven values one frame after `scrollTo`, so tests poll for them (T5.3)
- Safari jumps to an anchor while `PageTransition` still has the page 4px low (its fade-in starts at `translateY(4px)`), so it lands 1 to 2px short. The `#services` test allows 4px. T5.5 changes `page-enter`, so re-check then (T5.3)
- Tailwind v4 scans the whole project, `docs/*.md` included, so a class named in prose is emitted even when no component uses it. `reveal-left`, `reveal-right` and `reveal-stagger` were in the build from the start. Do not rely on that: their first real use guarantees them (T5.3)
- Side slides need an `overflow-clip` ancestor. A full-width card sliding in from the right pushes the page 8px wider at 375 until it lands, and the end-of-scroll guards cannot see it (T5.3)
- `animation-delay` does nothing on a scroll timeline, so stagger shifts `animation-range` instead. The individual `translate` and `scale` properties do not apply to inline boxes, so reveal `block` elements (T5.3)
- The sticky Navbar is 65px tall (`h-16` plus a 1px border), so `scroll-padding-top` is `calc(4rem + 1px)` (T5.3)
- A first run of the whole suite on a cold dev server can time out on one test. A rerun passes (seen once on WebKit in T5.3)
- A `:active` rule inside a custom block ties a Tailwind hover scale utility on specificity (two classes or pseudo-classes each) and loses on a mouse click, because the pointer is also hovering. The widget test read 1.1 (the hover scale) until `press` was written `:active:not(:disabled)`. Specificity decides it, not file order (T5.4)
- A custom `@utility` hover rule gets no hover media query for free. Wrap it in `@media (hover: hover)` (T5.4)
- A guard that reads elements cannot see `::before` or `::after`. `getComputedStyle(el, '::after')` is needed. A missing pseudo-element also reads `scale: none`, which means 1, so an underline test would pass with no underline: `InteractionAudit.scaleX` returns `NaN` for one that does not exist (T5.4)
- Checking that something did NOT happen (hover on a touch device) passes at once if you only poll. Wait a few frames first (`settleFrames`) (T5.4)
- `--ease-settle` suits things that arrive and stay (reveals, expands). It is wrong for an effect that must stay visible while it moves, because the motion is over in the first third. Judge a timed effect from stepped frames: pause `getAnimations()` at a set `currentTime` and screenshot (T5.4)
- Tailwind scans `docs/*.md`, so naming a utility in a brief emits it. The T5.4 brief put the 110% scale utilities in the build until it was deleted (T5.4)
- Playwright has no `expect.soft.poll`. Poll first, then use a soft check (T5.4)
