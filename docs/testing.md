# Testing

## Split of responsibility

| Layer        | Covers                                                                                                                                                                                                                                          | Excludes                                                                                          |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Vitest + RTL | Component correctness: props, variants, hrefs, ARIA, which block renders for each `type`. Route functions (`generateMetadata`, `generateStaticParams`) as plain functions                                                                       | Pure data files. `satisfies Record<Category, ...>` already proves completeness at compile time    |
| Playwright   | Routing and structure. `services-data.spec.ts` is data-driven: every slug from `getAllServices()` returns 200 with exactly one `h1`, unknown slug 404s, navbar to service page works. `about.spec.ts` and `not-found.spec.ts` cover those pages | Anything content-shaped: no coming-soon copy, no per-page specs, no section assertions, no counts |

Rule: Playwright asserts what is true because of routing and structure. Vitest asserts what is true because of props. Neither asserts content, because content changes as pages fill.

## Test first

1. Write tests from the spec approved in Stage 1, before the implementation.
2. Run them and confirm they fail for the right reason.
3. Implement until they pass.
4. Never edit or delete a test to make it pass without asking Haider.

## Gates (a ticket is not done until all pass)

- `pnpm lint`
- `pnpm typecheck` (`tsc --noEmit`)
- `pnpm test:unit`
- `pnpm build`
- `pnpm test:e2e` when a page or route changes, and at the end of each phase

## Vitest and RTL rules

- Colocated as `Component.test.tsx`. Config is `vitest.config.mts` and the environment is jsdom
- Assert on role, text and href. Never on CSS classes, with one exception: a test that a `className` prop reaches the element may use `toHaveClass`. The `LinkButton` variant and size tests still assert classes and are due a rewrite against exported constants or attributes
- Import exported copy constants instead of retyping strings. Do not hardcode literals or counts that change independently of logic
- Block and renderer tests use typed fixture data, never real service data
- `afterEach(cleanup)` is registered manually in `vitest.setup.ts` because `globals: true` is not set
- `vitest.setup.ts` also stubs `Element.prototype.scrollTo` and `window.matchMedia` (jsdom has neither) in a `beforeEach`, so every test gets fresh `vi.fn()`s and `matches: false`. A test changes one with `vi.mocked(window.matchMedia).mockImplementation(...)` (reduced motion) and the change cannot leak into the next test
- jsdom has no layout, so a scroll test fakes it with `Object.defineProperty` on `clientWidth`, `scrollLeft` and each slide's `offsetLeft` and `offsetWidth` (`ReviewsCarousel.test.tsx`). `requestAnimationFrame` is real (jsdom runs with `pretendToBeVisual`), so a test flushes a frame by awaiting one inside `act`. A spy on it also counts the test's own call, so count before awaiting. A test that passes before the code exists (a guard that is not triggered yet) is not proof: remove the guard and see it go red The wrap-around tests fake a layout that follows each slide's CSS `order` (slot n starts at n * 400) and can fake the browser's re-snap: it is installed before `render`, and the re-snap follows the slide the view was snapped to, not the current one, or the test passes with the bug in. jsdom's React does not interleave a hydration replay with the render that applies a client-only value, so that race is tested in Playwright only.
- jsdom ignores media queries, so desktop and mobile variants coexist in the DOM. Scope queries with `within()`
- RTL skips `aria-hidden` elements. Pass `{ hidden: true }` when you need them
- `vitest.config.mts` uses native `resolve.tsconfigPaths`; do not add `vite-tsconfig-paths`

## Playwright rules

- Specs live in `tests/`. Use the Page Object Model (PascalCase classes) and the custom fixture
- One spec file per page or feature, named for it (`about.spec.ts`, `not-found.spec.ts`), not grouped by the phase that built it
- Tag tests: `@homepage`, `@smoke`, `@navigation`, `@responsive`, `@services`, `@about`, `@notfound`, `@motion`, `@faq`, `@interaction`
- Playwright runs two projects, `chromium` and `webkit` (the Safari 26.5 engine, a stand-in for Safari because no iPhone is available). Install once with `pnpm exec playwright install chromium webkit`. Run one with `--project=webkit`. Firefox joins in T6.1. To test a production build, run `pnpm build && pnpm start` and then `pnpm test:e2e`: the config reuses a server already on port 3000 (stop it by its PID when done, or later runs test a stale build)
- WebKit differences to know: it has no `layout-shift` entries, so the CLS guard is skipped there (it would always pass). It updates scroll-driven values one frame after `scrollTo`, so poll for them (`expect.poll`). `requestAnimationFrame` inside `page.evaluate` never fires with JavaScript off, so scroll one `evaluate` call per step. A first run on a cold dev server can time out one test, rerun it
- Motion guards (`motion.spec.ts`, `MotionAudit`) read computed style, never a class name. Set reduced motion with `test.use({ contextOptions: { reducedMotion: 'reduce' } })`, because plain `reducedMotion` in `test.use` is ignored. The page-wide guards (faded, sideways scroll, layout shift, reduced motion, JavaScript off) run at phone and desktop from T5.6, written once and looped over `viewports`. Held fills, the reveal audit and the hero checks stay phone-only, by decision, to keep the suite quick (the hero call button is hidden from `lg`, so the load-in tests cannot run at 1280). Besides "nothing is left faded", the scroll-reveal guards need reveals to exist on the About page and four service pages (`revealAudit`), to have a live timeline on the page scroller (not captured by an `overflow-hidden` ancestor), and to hold no fill. One test checks a heading far below the fold goes 0, part-way, 1 and ends with no held `translate`. The JavaScript-off guard scrolls first, because a reveal below the fold is correctly hidden until reached. A guard that passes on a page with no reveal proves nothing, so the page list asserts reveals exist. A wrong service slug renders the 404 and passes the old guards, so check a new slug against `lib/services.ts`
- Homepage load-in guards (`motion.spec.ts`, T5.5) cannot look at the end state, because a timed effect has finished by then. `trackHeroFrames()` (call before `goto`, like `trackLayoutShift`) samples every frame from first paint for 2.5s: the h1's own and effective opacity (multiplied up its ancestors, since `PageTransition` carries one), whether any ancestor moved, the first-frame scale of the image and stripe, the first-frame opacity of the subtitle and call button, the sheen sweep's timing and the most animations running in `main`. Time tokens are read with `durationToken()`, because the build rewrites `150ms` as `.15s`. The reduced-motion poll cannot catch a missing guard on a timed effect (it finishes inside the poll), so `home: the hero starts no animation, even on the first frame` checks from frame one. Proven with a deliberate fault. Any init script that adds a style must wait for `document.documentElement` (a `MutationObserver`), or it throws and the observers after it are never registered
- `interaction.spec.ts` (`@interaction`, T5.4) covers hover, press, lift, sheen, the nav underline and the WhatsApp pulse. It is its own file because these need a desktop pointer and per-element targets, which the page-wide guards in `motion.spec.ts` do not have. T5.6 added two Why Choose Us checks here: a hovered card rises, and hovering changes no layout (`layoutBoxes()` reads each card's left edge and its `offsetWidth` and `offsetHeight`. A lift or reveal only moves things up and down and the offset sizes ignore transforms, so only a real layout change can alter them. `offsetLeft` and `offsetTop` are avoided: WebKit measures them from an animated ancestor while it reveals). `InteractionAudit` reads computed style of the element or its `::before` / `::after`, and animation timing. Distances come from the tokens in `globals.css` (`token()`), so retuning one does not break a test. Press is checked by holding the mouse down (`hold()`, never released, so nothing navigates), which applies `:active` in both engines. A pseudo-element that does not exist reads as `NaN`, so a missing underline can never pass as "fully drawn". A check that something did NOT happen (touch devices) waits a few frames first (`settleFrames()`), because polling passes at once. The pulse is proven from `getAnimations({ subtree: true })` timing (2 iterations, a delay, no held fill) and by calling `finish()`, never by waiting 6 seconds. The touch test uses `hasTouch` and `isMobile`, and asserts `(hover: hover)` is false first (Chromium and WebKit both report it). Data-driven press targets live in arrays at the top, one test each
- Reviews carousel (T5.7): `HomePage` reads where a review is on screen (`centredReviewIndex`, from the layout) as well as which one the state calls current (`currentReviewIndex`), and `waitForReviewsToSettle()` waits until `scrollLeft` has not moved for 10 frames, so a check never passes in the middle of a smooth scroll. The navigation tests (next arrow, click a neighbour, ArrowRight) run at both viewports, normally and with reduced motion. Proven by deliberate faults: no `scrollTo` (20 red), the `lg` slide at 40rem, the arrows without their `lg` placement, and no `preventDefault` (red only under reduced motion: a native snap step runs after an instant scroll, while a smooth `scrollTo` overrides it, so the ArrowRight test must keep its reduced-motion run) Wrap-around (T5.7 review): `waitForReviewsWindow()` waits until the slides have their `order` (the page has hydrated), `currentReviewIsInMiddleSlot()` reads that the window has turned, `swipeReviews(direction, input)` sends a sideways wheel (or a plain scroll for tests that chain swipes, because WebKit can read two quick wheel swipes as one gesture), and `reviewTintAlpha(index)` reads the hover tint from the `::after` overlay. Autoplay: Vitest fakes `IntersectionObserver` (jsdom has none) and the timers. Playwright installs `page.clock` after the page has loaded, so time keeps flowing, and `clock.fastForward(AUTOPLAY_INTERVAL_MS)` fires the due timer once, so no test waits out an interval. Wait for the root's `data-autoplay` (`running` or `held`) and then `waitForFrames()` before each jump. Keep one autoplay test on the real clock with the mouse over the carousel: the fake-clock tests could not see a hold on hover. A test that clicks or swipes a neighbour on the far side of the first card must wait for the window first, or Playwright's click scrolls a plain track. `A press made as the page loads still lands` reloads and clicks four times on purpose: the race it guards (a click replayed during hydration) failed about half the time before the fix.
- Reviews carousel depth (T5.8, `reviews-depth.spec.ts`, tagged `@motion` and `@homepage`): runs at phone, tablet (768, `tabletViewport` in `testData`, outside `viewports` so the page-wide loops do not grow) and desktop, and compares computed style with the `--depth-*` and `--star-rest` tokens (`token()`). Pause autoplay first (`pauseReviews()`). `HomePage.reviewDepth(i)` reads a card's scale, shift, tilt, ring, dim and star scales (ring and dim are `NaN` when the overlay does not exist, because a missing pseudo-element reads opacity 1), `reviewIndexBeside('left' | 'right')` finds the neighbours by screen position, `scrollReviewsOffCentre(i, fraction)` turns snapping off and holds a card part-way through its move (read the same card either side of the centre to prove the effect is mirrored), `reviewCardInset(i)` proves the peek, `reviewDotBars()` reads the dots' `::before`, `trackFirstReviewFrames()` samples the first card from first paint, and `watchReviewWindowTurn()` (start it without awaiting, then click) proves a window turn changes nothing on screen. `MotionAudit.carouselTimelineAudit()` checks every animation in the track runs on a timeline whose source is the track, is live and holds no fill. It exists because `revealAudit` cannot see these: the named timeline does not read as "view". The first-paint test samples scale and dim only: the ring's resting value (0) differs from the centred one (1), and Chromium applies a scroll timeline one frame after the first layout (the first `requestAnimationFrame` reads `currentTime` null), so a ring sample would flag a frame no one can see. The rest-state test covers the ring
- Touch and autoplay (T5.8 review): the autoplay bug (a finger on the carousel stopped it for good) only shows with real touch events, which Playwright has no API for. `HomePage.dragFingerOverReviews({ x, y })` sends `touchStart`, small `touchMove` steps and `touchEnd` through a CDP session, so those two tests (`Homepage - reviews autoplay, finger`) skip on WebKit (`test.skip` at describe level). They assert on the pause and play buttons (what the visitor sees), not `data-autoplay`, which also goes `held` when the carousel scrolls out of view. A drag of the page over the carousel must leave Pause showing, a sideways swipe must show Play. The Vitest cases (`a finger on a phone`) fire `pointerDown` with `pointerType: 'touch'`, and the "stops when the track scrolls under the finger" one was proven by removing the `touchingRef` stop in `handleScroll`. Hero and menu call buttons (`Homepage - hero call button`): the visible text (`useInnerText: true`) is just "Get a Quote" at 375 and keeps the number at 768. `toHaveText` reads `textContent` by default, which includes `display: none` text. `HomePage.mobileMenuCallLink` finds the menu's button by the `Mobile` nav label (`navLabels.mobile`)
- `MotionAudit.transitioningElementCount` also reads `::before` and `::after` (T5.4). Before, sheen, underline and ring transitions were invisible to the reduced-motion guard. Proven by a deliberate ungated transition on the sheen: the guard counted 3 to 5 per page, and 0 before the change
- A test of a click target must click where the old markup failed. The FAQ spec clicks the `details` row at 8px in (its padding), not the `summary`, because a click anywhere on a full-width `summary` already toggled it. Check the test is red against the old code before trusting it. To prove a motion is wired, read the animations on the element itself (`el.getAnimations()`), not the page-wide count, which an unrelated transition can satisfy
- Pick data-driven slugs in `getFaqServiceSlug()` (`testData.ts`), not a hardcoded service, so the placeholder FAQs can change without breaking the spec
- Use plain string assertions, not regex (`toHaveTitle('Team Autotech')`)
- Locators: `getByRole`, `getByText`, `getByLabel`. No XPath and no tight CSS selectors
- Use web-first assertions (`toBeVisible`, `toHaveText`). No `waitForTimeout`
- Keep tests deterministic: no `if/else` or loops inside a test, each test starts from a fresh page
- Pull URLs and test data from exported constants, not inline literals
- Structure as Arrange, Act, Assert. Use `expect.soft()` for several minor checks in one flow
- ESLint: `react-hooks/rules-of-hooks` false-positives on Playwright's `use` fixture parameter. A scoped override already exists in `eslint.config.mjs`

## Visual verification

For any visual change:

1. Start the dev server and screenshot the changed pages at 375, 768 and 1280 px wide.
2. Look at the images. Check overflow, clipped or wrapped text, spacing, token colours, and that nothing overlaps the Navbar or WhatsAppWidget.
3. Fix what you find, then re-check.

No screenshot script exists yet. Write a throwaway Playwright script outside the repo (details in `workflow.md`, Stage 2 step 4).
