# T4.3 — `ContactLinks` (tel / WhatsApp / mailto)

**Branch:** `T4.3` · **Commit:** `T4.3 - ContactLinks component and tests`
**Workflow:** Stage 1 = design review only (no code). **Reconcile with `ContactLine` before proposing anything.**

## Before

- The hrefs are built once in `lib/constants.ts`: `TEL_MOBILE_LINK`, `TEL_LANDLINE_LINK`, `WHATSAPP_LINK`, `MAILTO_LINK`. The display strings are `PHONE_MOBILE`, `PHONE_LANDLINE` and `EMAIL`.
- `ui/ContactLine` (promoted out of Footer in T2.6) renders one contact row. Footer and `FindUsSection` use it.
- Other places likely assemble the same links by hand: Navbar CTA, MobileMenu, `HeroSection` mobile CTA, `WhatsAppWidget`, and the T3 closing sections (`ServiceCtaBand` / `EnquiryBand`). **Unverified, so audit first.**
- There is no single "call / WhatsApp / email" group. The Project Plan's old file tree and numbering (T5.1) are stale. This ticket is T4.3 and lives in `ui/`.

## After

- `src/components/ui/ContactLinks.tsx`: Server Component with a `className` escape hatch. It renders Call, WhatsApp and Email actions, each with visible text, built only from the `constants.ts` exports. No href logic inside the component.
- At least one real consumer in this ticket: existing duplicates that match the shape are replaced. No dead component.
- No visual or behavioural regression in Footer, FindUs or the closing sections.
- T4.1 (About) no longer has a contact block (it was cut as a duplicate of the Footer). The first consumers are the closing sections (`EnquiryBand` callers). T4.2 can adopt it later if wanted.
- No contact form (decided: static links only).

## Decisions already made (don't re-ask)

| Decision                        | Choice                                                        | Why                                                                                           |
| ------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Source of hrefs                 | `constants.ts` only                                           | One source of truth. The old architecture doc's `wa.me` link is superseded by `WHATSAPP_LINK` |

## Decide in Stage 1 (these are the real judgement calls)

1. **Compose `LinkButton` or `ContactLine`?** `ContactLine` lists details and `LinkButton` is an action. Rule: if the first consumers (closing sections) want button CTAs, compose `LinkButton`. If they want a text list, compose `ContactLine`. Build one mode, and don't add a variant until a second consumer needs it.
2. **Which phone is the "Call" action?** Mobile (07515 007688) or landline (01282 787576)? Default: mobile for Call, with the landline kept in Footer and FindUs, because hours are Mon–Fri 10:00–17:30. Ask Haider to confirm with Syd.
3. **Button variants.** `LinkButton` primary on `bg-accent` is about 3.1:1 and fails AA until the real accent hex arrives. Pick variants knowing that. Don't modify `LinkButton` in this ticket.

## Edge cases and resolutions

| Case                                                  | Resolution                                                                                                                                                              |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phone numbers on desktop (no dialler)                 | Show the number as visible text, not just an icon                                                                                                                       |
| `mailto:` with no mail client                         | Show the email address as visible text                                                                                                                                  |
| WhatsApp prefill reads "Hi, How can we help?"         | That is the customer's message to the business, so it sounds like the business speaking. Unconfirmed with Syd. Don't change it here, and keep it listed as an open item |
| Email casing                                          | Use the `EMAIL` constant (lowercase). The old doc's capitalised form is irrelevant                                                                                      |
| Out-of-hours messaging or an "Open now" badge         | Needs Client JS and time zones. Out of scope                                                                                                                            |
| Replacing a duplicate would change its look           | Skip it and note it in the ticket doc. Don't force the component in                                                                                                     |
| Existing tests asserting structure of replaced blocks | Update to role/href assertions against the constants                                                                                                                    |
