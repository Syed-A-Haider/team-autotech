# T6.2 - Redirects for old WordPress URLs

Status: planned (urgent, the domain is live). Stage 1 needed.
Purpose: old WordPress URLs now return 404 on the live domain. Map the ones that have a real equivalent so Google, social links and the Google Business Profile do not land on a 404.
Depends on: nothing. Can run alongside T6.1.
Read first: `docs/architecture.md` (Routes), `docs/content/*.md` (old URLs in the briefs).

## Files

New `src/lib/redirects.ts` (plain data, no icon imports, read by `next.config.ts` through a relative import because the `@/` alias may not resolve there), `next.config.ts` (`redirects()`, `permanent: true`), `src/lib/redirects.test.ts`, `tests/redirects.spec.ts` (`@redirects`).

## Behaviour

- Map only real equivalents: old service slugs (for example `/stage-1-tuning/`, `/ghost-immobiliser-ii/`, `/scorpion-x-series-immobiliser/`) to `/services/<slug>`, old about or contact pages to `/about`
- Shop, product, basket, cart, checkout and my-account URLs keep returning the branded 404. That is the honest answer, not a redirect to home
- Build the source list from: the Wayback CDX list (`web.archive.org/cdx/search/cdx?url=teamautotech.co.uk/*`), a Google `site:` search, the three content briefs and Vercel 404 logs. Grow it later from the Search Console 404 report (T6.3)
- With and without a trailing slash. A slash may cost two 308 hops, which is acceptable

## Tests

Vitest: every destination is `/`, `/about` or `serviceHref` of an existing slug, no duplicate sources, no source shadows a real route. Playwright with `request` and `maxRedirects: 0`: each source returns 308 to the right place and the end page returns 200.

## Docs

`architecture.md` (Routes: redirects are platform config, the site is still fully static), `testing.md` (`@redirects` tag), close the old-URLs open item in `status.md`.

## Open

The exact old slugs are not known yet: the first step is collecting them.

## Out of scope

Redirecting shop or account URLs. A `/services` index (still a 404, by decision).
