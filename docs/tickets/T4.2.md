# T4.2 — Branded 404 (`not-found.tsx`)

**Branch:** `T4.2` · **Commit:** `T4.2 - Not found page and tests`
**Workflow:** Stage 1 = design review only (no code). No stakeholder input needed.

## Before
- No `app/not-found.tsx`. Unknown URLs, and `notFound()` calls from `/services/[slug]`, show Next's generic default 404, which is unbranded and has no way back into the site.
- The T3 Playwright spec ("unknown slug 404s") currently passes against that default page.
- Unconfirmed: whether `dynamicParams = false` is set in `services/[slug]/page.tsx`. If it isn't, an unknown slug is rendered on demand at runtime, which conflicts with the "fully static, no dynamic rendering" decision.

## After
- `src/app/not-found.tsx`: Server Component, one `<h1>`, a short plain explanation, and two actions. Primary: `LinkButton` to `/` ("Back to home"). Secondary: `LinkButton` to `/#services` ("View our services").
- It renders inside the root layout, so Navbar, Footer and WhatsAppWidget stay visible. It has no `<main>` of its own.
- `metadata` title "Page not found" via the root template. Copy lives in exported constants.
- The one file serves both unmatched URLs and `notFound()` calls. No per-route `not-found.tsx`.
- Responses are HTTP 404 with `noindex`.

## Verify first (repo)
1. Does `services/[slug]/page.tsx` export `dynamicParams = false`? If not, add it. It is one line, belongs with 404 behaviour, and must be flagged in the ticket doc.
2. After `pnpm build`, check the output for an unknown URL. Expect status 404 and a `<meta name="robots" content="noindex">` that Next adds itself. Don't hand-set robots unless it is missing.
3. Open the existing T3 Playwright 404 test and see what it asserts. Update it if it relies on the default page text.

## Decisions already made (don't re-ask)
| Decision | Choice | Why |
|---|---|---|
| Client "Go back" button | No | It needs state or history, so a Client Component. A link home does the job |
| Contact block / `ContactLinks` | Not on the 404 | Keeps this ticket independent of T4.3. Revisit once `ContactLinks` exists |
| Service suggestions | None | 4 of 6 popular services are coming-soon, so suggestions risk sending users to thin pages |
| Layout | `SectionWrapper` plus a large decorative "404" (`aria-hidden`) above the real `h1` | Matches existing primitives and keeps one h1 |
| Tone | Plain, no jokes | Customers are looking for a garage, not entertainment |

## Edge cases and resolutions
| Case | Resolution |
|---|---|
| `/services` (no index route by design) | Lands on the 404, and its "View our services" link recovers the user. Optional: a static `redirects()` entry `/services` → `/#services` in `next.config`. Raise it in Stage 1 and don't add it unprompted |
| Wrong-case or extra-segment URLs (`/Services/…`, `/services/x/y`) | Plain 404, no special handling |
| Old WordPress URLs (shop, basket, checkout, my-account, old product slugs) after T6.3 | Will 404 until a redirect map exists. **Out of scope here.** Note it in the ticket doc as a T6 task |
| `/not-found` typed manually | The Project Plan lists `/not-found` as a route, but Next serves it as an internal `/_not-found`. It 404s like any other URL, and no route is needed |
| Nested `<main>` | Layout already wraps children in `<main>`, so this page must not add another |

## Tests
- Vitest: one level-1 heading with the exported title constant. Both links have the right hrefs. The decorative "404" is `aria-hidden`. Rendered standalone, there is no `main` role (guards against nesting).
- Playwright (colocated with the existing T3 routing spec): an unknown top-level path and an unknown service slug both return 404 with one `h1`. The shell (Navbar) is present. The "Back to home" CTA navigates to `/`. Plain strings and exported constants only.
- Full suite green, with the new counts recorded in the ticket doc.

## Out of scope
Redirect map for old WordPress URLs (T6). Contextual 404 per service. Analytics. Search box. Fixing `LinkButton` primary contrast.

## Done when
Unknown URLs return a branded 404 inside the site shell, unknown service slugs are confirmed not to render dynamically (or `dynamicParams = false` is added), and the tests pass.
