# T5.7 - Reviews swipe carousel

Status: approved (Stage 1 done at phase level, 2026-11-05). Implement directly. If the code contradicts this brief, stop and flag it.
Purpose: swipe on phones, a lot more dynamic on desktop, and obvious ways to reach the next review. No autoplay (decided).
Depends on: T5.1.
Read first: `docs/design.md` (Motion).

## Files

`ReviewsCarousel.tsx` (stays the only Client piece), `ReviewsSection.tsx` if layout needs it, `vitest.setup.ts` (stubs), `ReviewsCarousel.test.tsx`, `motion.css`.

## Behaviour

- Track becomes `overflow-x-auto snap-x snap-mandatory` with hidden scrollbar and `overscroll-behavior-x: contain`. Native swipe and momentum. Slides `snap-center`
- Slide width: about 85% on phone (the next card peeks), 60% from `md`, 44% from `lg`, with end padding so first and last can centre. On desktop the centre card sits between the sides of its neighbours
- Navigation, all in one set of buttons (no duplicates): large prev and next arrows (at least 44px, bordered, accent on hover), placed at the track edges from `lg` and in the control row on phones; dots stay and the active one is clearly marked
- Clicking a neighbouring card centres it. Left and Right arrow keys move when the track is focused (`tabIndex={0}`, labelled). Home and End jump
- `currentIndex` stays state: set on click, and derived from scroll with an `onScroll` handler throttled by `requestAnimationFrame`. Keep the `aria-hidden={index !== currentIndex}` contract. Prev from the first wraps to the last and the reverse
- Scrolling uses `behavior: 'smooth'`, or `'auto'` when reduced motion is set. Write plain handlers (React Compiler is on, do not hand-memoise)
- No autoplay
