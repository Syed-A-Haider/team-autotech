## Footer numbers (worked out by hand, MEASURE IN THE PROBE FIRST)

A column's `view()` progress at the bottom of the page is `D / (window height + h)`: D is how far its top sits above the window bottom, h its height. The footer always ends at the window bottom at the bottom of the page. `reveal-stagger` child i ends at 30% + i x 3% (30, 33, 36, 39%).

| Window                | Row (height h)               | D    | `cover` progress | Result                                         | `entry` progress (D / h) |
| --------------------- | ---------------------------- | ---- | ---------------- | ---------------------------------------------- | ------------------------ |
| 375x812               | Brand and Links (~126px)     | ~459 | 0.49             | finishes                                       | 3.6                      |
| 375x812               | Contact and Hours (~232px)   | ~309 | 0.296            | part-faded (Contact ~0.79, Hours ~0.69)        | 1.33                     |
| 1280x800              | all four in one row (~212px) | ~305 | 0.301            | child 0 only just finishes, others ~0.9 to 0.7 | 1.44                     |
| 1280x1400 (no scroll) | one row                      | ~305 | 0.19             | a shortened `cover` range fails too            | 1.44                     |

An `entry` range reaches 100% when the column's bottom edge reaches the window bottom, so it finishes at any window height, even on a page that cannot scroll. The copyright row is not a column: it stays still (it could only finish at the last pixel of scroll).

## New motion.css blocks and tokens

1. **`reveal-stagger-entry`**: reuses the `reveal-up` keyframes and copies `reveal-stagger`'s `--i` steps. It is not a modifier on `reveal-stagger` (two blocks setting `& > *` at equal specificity would depend on CSS order, which T5.9 avoided). Child range: `entry calc(var(--i) * var(--entry-stagger)) entry calc(var(--entry-reveal-end) + var(--i) * var(--entry-stagger))`, with `animation-timeline` set after the shorthand. Tokens: `--entry-reveal-end: 60%`, `--entry-stagger: 8%`. Rule: `--entry-reveal-end + 5 x --entry-stagger` must be no more than 100%.
2. **`pop-once`**: new keyframes `pop-settle { from { scale: var(--pop-scale); rotate: var(--pop-rotate); } }`, applied as `animation: pop-settle var(--motion-slow) var(--ease-settle) var(--pop-delay) backwards`, behind the reduced-motion media query only (timed effect, no `@supports`). Reuses `--pop-scale` (0.5), whose `globals.css` comment becomes "where a badge starts". New tokens: `--pop-rotate: -6deg`, `--pop-delay: 600ms` (a literal, so `durationToken` can read it, not a `calc()` of `--hero-step`).

Estimated CSS cost: 0.3 KB gzipped or less.

## Behaviour

- Footer: the grid's four columns (Brand, Quick Links nav, Contact, Opening Hours) rise in turn on `reveal-stagger-entry`. The copyright row, social icons and links carry no reveal. Hovers stay colour only. The WhatsApp widget is untouched (a fixed sibling of `<footer>`, not a child)
- RelatedServices: heading unchanged. The grid is `reveal-stagger`, each `ServiceCard` sits in a `div.grid` wrapper (reveal on the wrapper, `lift` and `press` stay on the card, rows stay equal height)
- EnquiryBand (coming-soon, live CTA and About): heading unchanged. Pitch `reveal`. Contact row wrapper `reveal` (via `CONTACT_LINKS_STYLES`), buttons keep `press` and `sheen`. Glow static
- Badge chip (coming-soon only): `pop-once`, plays once at load, 600ms delay (the fourth hero beat), `--motion-slow`, `--ease-settle`. Scale and rotate are separate properties, so they compose with the chip's `-skew-x-12`. The un-skewed text span never animates. No opacity change, so the chip is never invisible and LCP is unaffected
- About: one plain `reveal` on each panel through `PANEL_STYLES` (intro facts panel, each of the four category cards, Find Us panel). No stagger, no side slides, no `underline-draw` on the category rows. The Find Us h2 keeps its own SectionHeading reveal inside the panel (it finishes first, so it only trails slightly). Fallback if the probe shows it looks wrong: no panel reveal on Find Us, heading only
- 404: unchanged
- Every scroll effect sits behind the reduced-motion guard and `@supports (animation-timeline: view())`. Reduced motion, no support and JavaScript off all show the finished page
