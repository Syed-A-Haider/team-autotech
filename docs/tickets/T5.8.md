# T5.8 - Carousel depth and polish

Status: approved (Stage 1 done at phase level, 2026-11-05). Implement directly. If the code contradicts this brief, stop and flag it.
Purpose: make the reviews carousel feel alive, mostly on desktop, with CSS only.
Depends on: T5.7.
Read first: `docs/design.md` (Motion).

## Files

`src/app/motion.css`, `ReviewsCarousel.tsx` (class names only), `ReviewCard.tsx`, `ReviewsSection.tsx`.

## Behaviour (all inside the scroll guard, using a `view(inline)` timeline per slide)

- Slides away from the centre scale down to about 0.9 and dim to about 0.55 opacity; the centre card is full size with an accent border. Without support, all slides look the same
- Desktop only (`lg`): a slight depth tilt on the side cards with `rotate: y` (about 8 degrees) and `perspective` on the track. Skip on phones
- Stars pop in one after another when a card first reveals (small `scale` stagger on the five star icons)
- Active dot is stretched into a short bar by scaling a pseudo-element, never by changing its width
- Heading and Google button use `reveal`

## Rules

Transform and opacity only. No layout change when the active card changes. Keep the first card readable at load (the entry range must not leave it dim on first paint).

## Tests

`@motion` guards (the dimmed side cards are intentional: the faded-element guard must still pass, so decide in Stage 2 whether dimming uses opacity or a colour overlay, and say which). Existing carousel tests unchanged.

## Manual check

Desktop 1280: depth looks smooth while arrowing and while dragging the scrollbar. Phone: no tilt, still smooth.

## Out of scope

Autoplay, new controls.

## Notes from T5.7 (facts the brief above did not know)

- The track is a native scroller (`overflow-x-auto`, `overflow-y-hidden`, snap). A `view()` timeline on a slide binds to the track, so use `view(inline)`. A block-axis `view()` inside it never runs, because the track has no block scroll (the star pop needs `view(inline)` or a timed effect)
- `MotionAudit.revealAudit` counts a timeline whose source is not the page scroller as captured (`detached`), so per-slide timelines inside the track will fail it. That guard needs an approved edit in T5.8
- The scrollbar is hidden, so "while dragging the scrollbar" in the manual check cannot be done. Use a trackpad swipe or Shift+wheel
- The dot is a button with a 32x44 tap target and the visible dot is its `::before` (`before:bg-muted`, active `aria-[current=true]:before:bg-accent` and `scale-125`). Stretch that pseudo-element by scaling it, with no DOM change
- Slides are the track's direct children, `w-(--slide) snap-center`, and clickable neighbours (`aria-hidden:cursor-pointer`) deliberately have no `press`. Do not add it: it would fight a scroll-driven `scale`
- The track has `py-3 lg:py-6` and `overflow-y-hidden` for the scale and tilt, so anything that grows past that is clipped. Also `ReviewCard` has no `className` prop (`conventions.md` says every primitive has one): add it if T5.8 needs a hook there
- `aria-hidden={index !== currentIndex}` is set on the server, so with JavaScript off slides 2 to 5 are hidden from assistive technology although visible. Already follow-up in `status.md`
