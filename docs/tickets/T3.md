## T3.5 — Video block

Status: Draft. Confirm the `video` member exists in the `ServiceSection` union. If T3.1 did not include it, add it here.

Purpose: Embeds a YouTube video on a service page without loading any third-party code until the visitor chooses to play it. Shows a poster image with a play button, then swaps in the iframe on click.

Depends on:

- `ServiceSection` union (T3.1)
- `ServiceSections` renderer (T3.4), which gains a `video` case
- First consumer: Ghost Immobiliser II (T3.7)

Files (in `components/service-sections/`, each with a colocated test):

- `VideoSection.tsx`: Server wrapper that owns heading and caption
- `VideoEmbed.tsx`: Client, the only interactive piece (`playing` state)
- `ServiceSections.tsx`: add the `video` case

Props / data shape:

- `VideoSection` takes the whole section object, per convention.
- `VideoEmbed` takes only serialisable primitives: `videoId: string`, `title: string`, `poster: string`.
- The play icon is imported inside `VideoEmbed`, never passed in as a prop.

Behaviour:

- Initial render: poster image plus a play button. No iframe, and no request to any third party.
- On click: the poster is replaced by an iframe pointing at the embed URL for `videoId`, with autoplay on. The iframe must have a `title`.
- The container has a fixed aspect ratio (16:9) in both states, so the swap causes no layout shift.

Accessibility:

- The trigger is a native `<button>` with an accessible name like "Play video: {title}". The icon is `aria-hidden`.
- The iframe has a descriptive `title`.
- When the button is replaced by the iframe, focus moves to the iframe so keyboard users are not dropped back to the top of the page.

Tests (Vitest + RTL + user-event):

- Before click: play button present, poster present, no iframe.
- After click: iframe present with `src` containing the video id and the correct `title`; play button gone.
- Assertions use exported constants or the test's own props, not hardcoded duplicates.
- No Playwright. The first real video arrives at T3.7.

Out of scope:

- Self-hosted video
- Playlists
- Captions or transcripts
- Analytics

Open questions for Stage 1:

1. Poster source: a local image in `public/` (needs a frame grab or an image from Syd), or YouTube's thumbnail URL? The thumbnail is a third-party request on page load, which contradicts the confirmed decision "no third-party embeds on page load". Local is the consistent choice.
2. Embed domain: standard YouTube or the privacy-enhanced `youtube-nocookie.com`?
3. What does the block render if a video has no poster? Options: a dark surface with the play button, or require a poster in the type.
4. Where do the real video ID and poster for Ghost Immobiliser II come from? This needs Syd before T3.7.
